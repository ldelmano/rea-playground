Limites: web search retornou pouco; vários domínios primários (EUR-Lex, Planalto, vbdecompiler.com) ficaram inacessíveis (DNS bloqueado), e a API do GitHub estava bloqueada. Itens marcados [BC] vêm de conhecimento prévio, não verificados agora. Nada aqui é aconselhamento jurídico.

## A. REA
- Repo https://github.com/morluto/rea (MIT; avisos de terceiros em THIRD_PARTY_NOTICES.md). Pacote npm `rea-agents` (https://socket.dev/npm/package/rea-agents). Também listado em https://skills.sh/morluto/rea/reverse-engineer-anything e https://glama.ai/mcp/servers/sojwmpw4ha.
- Mantenedor: apenas o usuário/org "morluto"; nenhum nome de pessoa ou empresa na página. Não consegui ver contribuidores (GitHub API bloqueada). Incerto.
- Escopo declarado: binários nativos (Hopper, Ghidra, IDA, JEB via cliente), .NET, APKs (JADX headless, Apktool, adb), Electron/JS, web, firmware (Binwalk/Unblob), Go/WASM/EVM, comportamento de processo. Roda local e registra-se em Claude Code, Codex, Cursor, Gemini CLI. Diz explicitamente que NÃO afirma recuperar o código-fonte original nem clonar apps automaticamente; o aviso limita o uso a pesquisa lícita e software próprio/autorizado. Ghidra e IDA são "traga o seu" (REA não instala Ghidra nem Java); ferramentas comerciais precisam de licença própria.
- Menções externas: só agregadores/divulgação. Thread de Matthew Berman (via https://runtimewire.com/article/matthew-berman-rea-ai-reverse-engineering, não consegui abrir), GitHub Trending em out/2026 (https://aitoolly.com/ai-news/article/2026-10-08-rea-surfaces-on-github-trending-leveraging-ai-agents-to-reverse-engineer-software-from-application-b), post Telegram https://t.me/s/SkipCI/189, release 4.1 em https://ai-tldr.dev/releases/morluto-rea-4-1/. Não achei threads de Hacker News/Reddit nem reviews técnicos independentes.
- Incoerências a tratar como incertas: estrelas (sidebar do GitHub ~151k; fontes secundárias citam ~400, 14,9k, 110k), nº de ferramentas (42 a 70), versão npm (3.1.0 numa página vs 4.1.0 em agregador), Node (22 vs 24). Contagens tão divergentes pedem verificação direta antes de se confiar em "popularidade". Projeto muito novo; maturidade para uso em produção não demonstrada.
- Relevância ao caso: o foco de REA é Linux x64 (Windows x64 experimental; suporte DOS 16-bit experimental citado). Ghidra via REA é somente leitura. Para sistemas legados Windows em Delphi/VB6/PowerBuilder, REA ajuda como camada de agente sobre Ghidra/IDA, mas as ferramentas específicas da seção C recuperam mais estrutura (formulários, eventos).

## B. Ferramentas comparáveis (todas: ponte MCP sobre um engine)
- GhidraMCP (LaurieWired), Apache-2.0, ~5,5k a 9k estrelas conforme snapshot: https://github.com/LaurieWired/GhidraMCP , https://www.sourcepulse.org/projects/1989626
- ida-pro-mcp (mrexodia), MIT, ~10k estrelas (agregador, https://dev.co/ai/mcp/ida-pro-mcp); exige IDA Pro (comercial).
- re-mcp (jtsylve), multi-backend IDA/Ghidra, https://pypi.org/project/re-mcp/ (IDA 9+ licenciado).
- ReVa (extensão Ghidra, modelo-agnóstico, online/offline): licença e estrelas não verificadas.
- Binary Ninja MCP (fosdickio) e JADX MCP (zinja-coder): existem; licença/estrelas não verificadas. Binary Ninja é comercial.
- Comparação: os projetos acima são um engine por servidor, mais maduros e com comunidade maior. REA é mais amplo (muitos alvos, "evidence bundles", verificação de reconstrução) mas muito mais recente e de mantenedor opaco. Para um binário nativo de negócio, GhidraMCP (gratuito, Apache-2.0) é a base segura e barata; REA acrescenta fluxo orientado a evidência.

## C. Ferramentas padrão por tecnologia ([BC] salvo indicação)
- Delphi: IDR (Interactive Delphi Reconstructor), Delphi 2 a XE4 segundo o README, https://github.com/a1ext/IDR ; recupera classes, formulários (DFM), nomes de métodos, não código-fonte completo; gratuito. DeDe: antigo, Delphi até ~7, gratuito. Delphi recente: Ghidra/IDA + plugins (ex.: ferramentas de DFM).
- Visual Basic 6: VB Decompiler (DotFix), Lite gratuito, Pro pago (preço não verificado: https://www.automation.com/article/gpch-soft-releases-visual-basic-decompiler). P-Code é razoavelmente recuperável; código nativo, só pseudocódigo. Recupera formulários e eventos.
- .NET Framework: ILSpy (MIT, gratuito), dnSpy/dnSpyEx (GPL, gratuito, depurador; original arquivado), JetBrains dotPeek (gratuito), ofuscação é o principal risco. Recuperação de C#/VB.NET geralmente próxima do original, sem comentários.
- Java: JADX (Apache-2.0), CFR (MIT), Vineflower (Apache-2.0); todos gratuitos. Bytecode recupera quase tudo.
- PowerBuilder: PBD/PBL com p-code; ferramentas comerciais de nicho (ex.: PB Decompiler/PBKiller) — nomes e preços não verificados. Incerto.
- Visual FoxPro: FoxPro compila para objetos que preservam bastante estrutura; ReFox (comercial) é a ferramenta clássica — não verificado.
- Clipper/Harbour: Clipper compilado quase sem decompiladores confiáveis; existem utilitários de recuperação parcial (ex.: "Clipper decompiler" históricos), sem garantia. Harbour é código aberto, mas aplicações compiladas viram C/nativo. Frequentemente os dados (DBF/NTX) e telas são a melhor fonte. Incerto.
- Para tudo o que é nativo sem decompilador específico: Ghidra (Apache-2.0, gratuito), IDA (comercial), Binary Ninja (comercial).
- Dados: em sistemas de negócio, esquema de banco, relatórios, logs e comportamento observável costumam dar mais entendimento do que o código recuperado.

## D. Noções jurídicas (alto nível; não é aconselhamento jurídico)
- UE, Diretiva 2009/24/CE (versão codificada da 91/250/CEE): art. 5(3) permite ao utilizador legítimo observar, estudar ou testar o funcionamento do programa para perceber as ideias e princípios subjacentes, durante operações de carregamento/execução que ele está autorizado a fazer. Art. 6 permite descompilar sem autorização do titular apenas se indispensável para obter informação necessária à interoperabilidade de um programa independente, por licenciado ou pessoa autorizada, se a informação não estiver já facilmente acessível, e limitado às partes necessárias; a informação não pode ser usada para outros fins nem para desenvolver programa substancialmente similar. Art. 8: cláusulas contratuais contrárias a 5(2),(3) e 6 são nulas. Texto: legislation.gov.uk (https://www.legislation.gov.uk/eudr/2009/24/article/6) e EUR-Lex (não consegui abrir). Ver também TJUE C-406/10 (SAS Institute).
- Portugal: o DL 252/94 transpôs a Diretiva 91/250/CEE (https://diariodarepublica.pt/dr/detalhe/decreto-lei/252-1994-625995); WIPO Lex o marca como substituído (https://www.wipo.int/wipolex/en/legislation/details/3522), mas não identifiquei o diploma que o substituiu nem o artigo exato da descompilação. Verificar a versão em vigor antes de citar.
- Brasil: Lei 9.609/1998 (texto: https://cinttec.ufs.br/uploads/page_attach/path/1083/Lei_N__9.609_98_-_Lei_de_programas_de_computador.pdf). [BC] Art. 6 lista usos que não ofendem direitos do titular, incluindo a integração de programa a sistema por usuário e a semelhança por limitações técnicas; o Brasil não tem cláusula expressa de descompilação para interoperabilidade como o art. 6 da diretiva, então analisar além do uso licenciado é zona mais incerta. Não verifiquei o texto.
- Ponto-chave: se o cliente é o titular dos direitos (software feito sob encomenda cujos direitos foram cedidos, ou desenvolvido por empregados), a análise é em princípio livre; se o cliente é só licenciado de software de terceiro (ERP/SDK embutido, bibliotecas), valem os limites acima e o contrato. Em software sob encomenda de um fornecedor externo, ver quem detém os direitos (em Portugal, [BC] a regra geral favorece o autor/contratado salvo cessão expressa). Recomenda-se confirmar a titularidade por escrito antes de começar e guardar a prova.
